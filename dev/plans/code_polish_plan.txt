Rules for every step (read them again at each step)
---------------------------------------------------
 1. One file, or one finding, per step. Read the whole function before changing a line of it.
 2. Behaviour stays the same. No renamed public name, no changed signal, no changed text shown to the user
    (a changed text needs a translation: the user writes those, the .po files are not touched).
 3. Tests: only those of the files touched, found with
      grep -rlE "<module name>|<class name>" dev/tests
    and run with  QT_QPA_PLATFORM=offscreen .python/bin/python3 -m pytest -q -n 6 <files>.
    Never the whole suite, never on the real display, never an application-wide event filter.
 4. A test that fails is not edited to pass. Undo the change (git checkout -- <file>) and write the finding
    in the report instead.
 5. Not sure whether something is dead, or safe? Do not change it: one line in the report.
 6. Comments say why, in the project's tone (short, plain English). No comment that repeats the code.
 7. No commit unless the user asks. At a commit: the size line in todo.txt, and dev/appsize.csv.
 8. Stop after each batch with a report: file, what changed, lines removed, tests run, what was left alone.
